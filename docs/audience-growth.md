# 認知と継続読者を育てる運用（2026-10-21〜2027-01-18）

## 発信の軸

気になったものを自分で試し、作り、暮らしや仕事がどう変わったかを、自分の言葉で書く。
AI・開発・ガジェット・日常を扱う。一般論だけの記事、試していない体験、裏付けのない成果は書かない。
主目標は認知・再訪・継続的な反応。アプリ送客は参考値。新しい購読サービス・広告は導入しない。

Xプロフィール用文案（サイトと同じ軸。アカウントには未反映）:
> Webエンジニア / 個人開発者。気になったものを自分で試し、作り、暮らしや仕事がどう変わったかを書いています。AI・開発・ガジェット・日常。ブログとWeekly Logで、試行錯誤の続きを。

## 毎週の運用

- 主力記事1本（3時間）: 読者の疑問 → 自分で確かめたこと → 結果と限界 → 読者が試せる一歩。
- Weekly Log 1本（1時間）: 前回の予告を回収 → 今週いちばん考えが変わったこと → 次に試すこと。
- 記事は週2本を上限とする。忙しい週は主力記事を優先し、連載は短縮。埋め合わせはしない。
- X週4投稿と会話（1時間）: 主力記事の発見、途中の画面・気づき、迷った判断、連載の要点。会話は週3回15分、残り15分で投稿文を整える。
- 改善・分析（1時間）: 数字と読者の反応を記録し、次の仮説を1つ決める。
- 余力は実体験・取材・既存記事改善へ。投稿数自体を目標にしない。

投稿・公開時は各配信先の既存手順を使う。この文書の追加だけでは予約投稿や自動返信は開始しない。
記事制作前にこの文書と `templates/weekly-log.md` を参照する。
Weekly Logのfrontmatterに `series: weekly-log` を付けると一覧と初回・前回・次回が自動更新される。
タイトルは「具体的な出来事 — AI Weekly Log #番号」。公開済み記事のslugは変更しない。

判断: 継続して反応されるテーマは深掘り。PVだけ伸びたテーマは入口として別評価。母数不足は「判断保留」。

- 初回・最新回には存在しない前後リンクを出さない。下書きを含めない。
- 既存記事URLを維持。関連記事は自分自身を選ばず、共通タグがなければ入門ページへ案内。
- GA4は本番のみ有効。検証用IDと通信の遮断・モックで初回表示、遷移、戻る、1クリック1イベントを確認。
- 本番反映後は実際のGA4受信を確認。確認アクセスは運用記録に記載する。
