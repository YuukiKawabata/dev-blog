# 振り返りと学習

ユーザーは「最近全くチェックしていない」と言っている。**誰も見ていない前提で、学習が自動で回る必要がある。**
そのぶん、記録を残さないまま進むことが一番のリスクになる。

## SNS側の仕組みには書き込まない

SNS（X）の運用は 2026-10-03 に v7 へ切り替わった（`hasshin/sns/README.md`）。投稿は本人が書き、
AIは週1回の下書きと振り返りだけを用意する。v6 までの台帳・投稿実績CSV・研究ノートは
iCloud の `個人/SNS/_バックアップ_v6_2026-10-03/` に移されて**廃止**されている。触らない。

記事配信で X に投稿した告知は、**記事側の記録（`記事実績.csv` の「X告知URL」列）にだけ残す。**
SNS側に別の記録を作らない。データが二重管理になって両方が腐る。

## 記事を公開したら必ず記録する（⑫の実体）

### 1. 記事側の実績へ

`$H/articles/実績/記事実績.csv` に1行足す。公開直後は数値が空でよい。
X告知の投稿URL（`https://x.com/Yuki_K25/status/<threadRootId>`）を「X告知URL」列に入れる。
`threadRootId` は `.x/state.json` の `articles.<x.slug>` にある。

### 2. 記事研究ノートへ

`$H/articles/記事研究.md` の研究ログに、その日の実測と学びを追記する。
**仮説（A番号）を立てて、次に何を試すかまで書く。** ここが学習の本体。

## 週次レビュー（記事側）

SNS側は日次の学習スロットが回っているので、記事側は週次で足りる。

1. `記事実績.csv` の数値を埋める
   - **Zennのいいね**: 記事ページをブラウザで開いて読む
   - **Xのインプ・いいね**: 告知の投稿URLを開いて読む
   - **note のスキ**: note の記事ページ
   - **ブログPV・読了率・流入元**: `npm run analytics:report -- --from <公開日> --to <昨日>` で出す（GA4、2026-10-14〜。
     手順は `docs/analytics.md`）。前日までのデータしか出ない。Search Console は2〜3日遅れ
2. `記事研究.md` の「検証中の仮説」を更新する
   - 支持されたら「確定パターン集」へ昇格
   - 反証されたら「棄却した仮説」へ移す。**理由を書く**
3. 「今の指針（最大5行）」を書き換える。次に記事を書くときはここが最初に効く

### 数値の測り方

**Zennのいいね**は curl で取れる。記事HTMLに `"likedCount":N` が埋まっている。

```bash
curl -s -L "https://zenn.dev/yuukikawabata/articles/<zenn.slug>" | grep -oE '"likedCount":[0-9]+'
```

URLは記事の frontmatter の `zenn.slug` から機械的に導ける。**過去記事も全部測れる。**
「URLが残っていないから測れない」は誤り（2026-08-11に一度この判断ミスをした）。

**Xのインプ・いいね**はブラウザで開いて読む。curlでは取れない。

### ステータスコード200を成功の証拠にしない

**x.com も zenn.dev も、存在しないURLに対して200を返す。** どちらもSPAで、
アプリのシェルだけ返してくるため。過去に2回これで誤った判断をしている。

- x.com: 投稿の有無を200で判断してしまった
- zenn.dev: 存在しないslugでも200が返ることを確認済み

**中身で判断する。** Zennなら `likedCount` の有無、Xならブラウザで実際の画面。

### その他

- 計測時刻を必ず記録する。投稿から何時間後かで数字は大きく変わる
- n=1 の結果を確定パターンに昇格させない。SNS側の研究ノートも複数回の再現を待っている
- 測れなかった項目は空のままにする。**推測値を入れない**

## 未整備なもの（正直に書いておく）

- **ブログのPVは 2026-10-14 から GA4 で測れる。** それより前の記事は計測がないので、Zennのいいねと
  Xのインプを代理指標にする。記事別のPV・読了率・流入元・アプリ送客は `npm run analytics:report`
- **note のスキ数**は手で読むしかない
- **転載先からのブログ流入**は、UTM（`utm_source=x / zenn / note`）を付けたリンクからだけ数えられる。
  Zennの既存記事（2026-10-14以前）は末尾リンクにUTMが無いまま（`publishing.md` ⑨）

## 定期実行について

このスキルは呼ばれたときにしか動かない。**週次レビューを自動で走らせるには、
ユーザー側のスケジュール設定に登録する必要がある**（SNS側の日次自動化と同じ仕組み）。

登録されていない場合、レビューは記事公開のついでに実行するしかない。
その場合は、公開時に前回公開分の数値を埋める運用にする。
