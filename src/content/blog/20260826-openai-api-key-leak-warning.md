先日、OpenAIから「APIキーで不審なアクティビティを検知しました」という件名のメールが届きました。差出人は `trustandsafety@tm.openai.com`、内容は「使用状況を確認してほしい」「心当たりがなければキーをローテーションしてほしい」というものです。

正直、最初に頭をよぎったのは「これはフィッシングではないか」ということでした。件名の煽り方も、対応しないとキーを失効させるという書き方も、ソーシャルエンジニアリングの典型パターンに見えたからです。

## 「不審なアクティビティを検知しました」

個人開発やSES案件を並行していると、こういう警告メールは月に何通も届きます。そのほとんどは実際にはただの定型通知か、悪くてもフィッシングです。慣れているぶん、反射的に「どうせ煽りだろう」と流したくなる自分がいました。

## まず疑うところから

とはいえ、実際に漏洩している可能性もゼロではありません。感情的に無視も信用もせず、まず送信ドメインを確認することにしました。OpenAIの公式ヘルプセンターには正規の送信ドメイン一覧が公開されていて、そこに `tm.openai.com` がワークスペース招待やトランザクションメール用のドメインとしてきちんと含まれていました。本文にも認証情報の入力を求めるような不自然なリンクはなく、書かれている内容自体は「使用状況を見直す」「怪しければローテーションする」という妥当なセキュリティ対策の案内でした。

ここで、これは無視していい話ではなさそうだと判断し、実際にOpenAIのダッシュボードを自分で開いて確認することにしました。もちろんメール内のリンクは踏まず、いつも通りブラウザで `platform.openai.com` に直接アクセスしています。

## ダッシュボードを見て青くなった

自分のOpenAIアカウントには複数のプロジェクトがあり、それぞれにAPIキーがぶら下がっています。メールに書かれていたキーの末尾（下4桁）と一致するものを順番に探していくと、Default projectの中に `expo-app` という名前のキーが見つかりました。

このキーの作成日は2024年8月。つまり作ってから丸2年ほったらかしにしていたキーでした。ところがUsageの画面を見ると、直近7日間のグラフはずっと0円のまま横ばいだったのに、まさにその日だけ突出したバーが立っていました。451件のリクエスト、72万5000トークン、金額にして6.25ドル。すべて同じキー経由で、しかも今日この日に集中していました。

2年間ほぼ動いていなかったキーが、その日だけ急に451回も叩かれている。これはもう「漏洩したキーが第三者に使われている」以外の説明がつかない状況でした。

## 犯人捜し：自分のどのアプリが使っていたのか

キーを失効させる前に、まず自分の環境でこのキーを使っているアプリがないか確認することにしました。いきなり失効させて、実は裏で動いている本番アプリが壊れる、というのは避けたかったからです。

キーの名前が `expo-app` だったので、まずExpoのダッシュボードを確認しましたが、自分が持っている2つのExpoプロジェクトの環境変数には該当するキーは登録されていませんでした。次にGitHubで自分の全リポジトリを対象に `OPENAI_API_KEY` や `openai` というキーワードでコード検索をかけたところ、実際にOpenAIを呼んでいるリポジトリは2つだけで、そのどちらも別の現役キーに紐づいていました。さらに、あるアプリの設計書に「Supabase Edge Functions経由でOpenAI APIを使う」という記述を見つけたので、そのSupabaseプロジェクトのシークレット設定まで確認しましたが、実際に登録されていたのはOpenAIではなくGeminiのキーでした。

一通り自分の資産を洗った結果、このキーに依存している現役のアプリはどこにも見つかりませんでした。おそらくどこかの古い開発環境や、一度だけ試しに貼り付けてそのまま忘れていた場所から漏れて、今回のように第三者に悪用されたのだと思います。

## 失効、そしてついでの棚卸し

依存しているアプリがないことを確認できたので、そのままダッシュボードからキーを失効させました。表示は即座に「revoked」に切り替わり、以降そのキーでのリクエストはすべて拒否されるようになります。

ここで終わってもよかったのですが、せっかくAPIキーの一覧をひと通り眺めたので、この機会に他のキーも棚卸しすることにしました。プロジェクトごとのキーに加えて、レガシー扱いになっている「User API Keys」のタブも含めて全件チェックしたところ、月間利用額が0円で、直近の利用日が半年〜2年以上前という放置キーがさらに5件見つかりました。あるアプリ開発サービス経由で自動発行されたキー、作成したまま一度も使われていなかったキー、テスト用に作って役目を終えていたキーなどが混ざっていました。唯一、直近でも実際に使われていたキーだけは残し、それ以外の6件をまとめて失効させました。

## 今回の教訓

一番の教訓は、セキュリティ通知メールを「どうせフィッシングだろう」と決めつけて無視しないこと、かといって鵜呑みにしてリンクをクリックしないこと、その中間として送信ドメインとダッシュボードの実データを自分で確認する、という一手間を惜しまないことだと思います。今回はその一手間のおかげで、本当に2年前のキーが漏洩して悪用されている現場を見つけられました。

もうひとつの教訓は、APIキーは「作ったら終わり」ではなく定期的な棚卸しが必要だということです。使っていないキーほど本人の記憶からも消えていくので、漏洩に気づくタイミングも遅れます。今回のようにOpenAIから通知が来なければ、おそらくずっと放置されたままだったはずです。

個人開発やSES案件をいくつも並行していると、APIキーの数は思っている以上に増えていきます。この記事を読んで思い当たる人は、一度自分のOpenAI（に限らず各種SaaS）のAPIキー一覧を開いて、最終利用日と月間利用額を眺めてみることをおすすめします。
